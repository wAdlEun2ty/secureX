# Governance of SecureX

## 1. Project Leadership
SecureX is maintained by **wAdlEun2ty** as the project lead. Responsibilities include:
- Approving major architectural changes
- Reviewing pull requests for critical components
- Managing releases and versioning
- Maintaining security and privacy standards

## 2. Core Team
- **Contributors**: Developers who contribute code, tests, or documentation
- **Reviewers**: Trusted contributors who can approve pull requests
- **Maintainers**: Contributors with merge rights to the main branch

## 3. Contribution Process
1. Fork the repository
2. Create a feature branch
3. Implement your changes
4. Submit a Pull Request
5. Pull Request reviewed by at least one Maintainer
6. Merge after approval

> Note: Security, core algorithms, or critical fixes require review from the Core Team Lead.

## 4. Decision Making
- **Minor changes** (documentation, non-critical fixes) can be merged by any Maintainer.
- **Major changes** (architecture, algorithms, API changes) require Core Team Lead approval.
- **Disputes**: Any disagreements can be escalated to the Project Lead.

## 5. Release Management
- Follows semantic versioning: `major.minor.patch`
- Version bumps:
  - **Patch**: Bug fixes or minor improvements
  - **Minor**: New features without breaking API
  - **Major**: Breaking changes, API redesigns, or critical updates

## 6. Security & Privacy Oversight
- Security issues are handled according to `SECURITY.md`
- Privacy practices are maintained according to `PRIVACY_POLICY.md`
- Security-critical changes require explicit Core Team review

## 7. Community Guidelines
- All contributors must follow `CODE_OF_CONDUCT.md`
- Support and discussions via GitHub Issues, Discussions, or the provided channels

## 8. Transparency
- Decisions, releases, and discussions are public via GitHub
- Governance documents are versioned with the repository
- All pull requests, issues, and code changes are traceable

## 9. Updates to Governance
- Changes to governance require Core Team Lead approval
- Major governance changes are announced in GitHub Releases
