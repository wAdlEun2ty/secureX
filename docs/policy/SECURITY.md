# Security Policy for SecureX

## Overview
SecureX is committed to maintaining the highest security standards. This document outlines our security policies, how to report vulnerabilities, and our approach to handling security issues.

## Supported Versions
We only provide security support for the following versions:
- `v1.x` (latest minor/patch updates)
- Only the most recent major version is actively maintained.

Please upgrade to the latest version to ensure you receive security patches.

## Reporting a Vulnerability
If you discover a security vulnerability, please report it privately to ensure safe handling:

- Email: [wAdlEun2ty@tuta.io](mailto:wAdlEun2ty@tuta.io)  
- PGP Key: *Provide PGP key for encrypted reports (optional)*

Do **not** open a public issue for security vulnerabilities. This ensures the safety of our users.

### Required Information
When reporting, please provide:
- Detailed description of the vulnerability
- Steps to reproduce the issue
- Affected versions
- Any suggested fixes or references

## Response Process
1. Confirm receipt of your report within 24 hours.
2. Assess and validate the vulnerability.
3. Work on a fix or mitigation.
4. Release a patched version.
5. Publicly acknowledge the reporter (if they wish) once patched.

## Disclosure Policy
- We follow **responsible disclosure**.  
- Vulnerabilities will be disclosed publicly only after a patch is available.  
- Users should upgrade promptly to avoid exposure.

## Acknowledgements
We are grateful to anyone who responsibly reports security issues and contributes to improving SecureX.
